# AlgebraicCurves / JacobianVarieties library scope

Current build state and restart instructions are in [RunState.md](RunState.md).

This document fixes the intended scope and dependency direction before the next
full build.  It is a pruning contract, not a list of everything that happened to
be generated by the original FLT-oriented campaign.

## Goal

The maintained library covers algebraic curves at roughly Hartshorne level and
the general Picard/Jacobian construction needed on top of that theory.  A module
is retained only when it is part of that mathematical core, supplies a genuinely
reused missing prerequisite, or is a small canonical example of the core API.

## Dependency layers

1. `AlgebraicCurves.Foundations` contains only reusable prerequisites missing
   from Mathlib: commutative algebra, field theory, category theory, and
   homological algebra.
2. `AlgebraicCurves.Geometry`, `FunctionFields`, `Places`, `Valuations`,
   `Divisors`, `Differentials`, `Cohomology`, `Models`, `RelativeDivisors`, and
   the required Hilbert machinery form the curve layer.
3. `JacobianVarieties.Picard`, `Pic0`, `Autoduality`, and `WeilPairing` form the
   Jacobian layer.  Reusable abelian-scheme and relative-group-law results live
   in `AlgebraicCurves.Geometry.AbelianSchemes`, below that layer.
4. Nodal/glued Picard theory is retained as generalized-Jacobian support when it
   is used by the Picard and Riemann--Roch layers.

The intended dependency direction is one-way:

```text
Foundations -> Algebraic curves -> Picard/Jacobian -> optional examples
```

In particular, `AlgebraicCurves` must not depend on arithmetic campaigns or on
high-level `JacobianVarieties` implementation modules.  Existing reverse edges
identify misplaced definitions or theorem cards and must be removed by moving
the smallest reusable API to the lower layer.

## Remove after extracting reusable API

- Galois-representation and patching campaigns.  Keep only the generic
  localized-rational, depth, Cohen--Macaulay, adic-topology, and flatness facts
  actually used by the curve/Jacobian core, under mathematical core names.
- Elliptic-curve Tate/Galois/ramification arithmetic.  Keep only the generic
  Picard pushforward API and a minimal Weierstrass/Legendre example surface.
- Finite-field Frobenius counting and L-polynomial campaign, except for a small
  lower-level finite-field lemma if a retained core theorem genuinely requires
  it.
- FLT preliminaries, modular-level infrastructure, complex analytic/integration
  campaigns, Grassmannians, broad polynomial-combinatorics campaigns, probes,
  and generated historical branches.

## Retain but rename or split

- The former `JacobianVarieties.GoodReduction` package was split: reusable
  abelian-scheme and relative-group-law theory moved to
  `AlgebraicCurves.Geometry.AbelianSchemes`, while the arithmetic reduction
  campaign was removed from the maintained core.
- `AlgebraicCurves.Arithmetic.Isogenies.Isogeny_ConditionalCurrency` mixes a
  generic `Pic0` pushforward construction with genus-one isogeny material.  The
  generic part moves to `JacobianVarieties.Pic0`; the special-purpose tail does
  not remain in the core.
- `AlgebraicCurves.Arithmetic.LocalTheory` mixes reusable local commutative
  algebra with patching-specific predicates.  Those parts are split rather than
  retaining the misleading arithmetic package.

## File-layout invariants

- One mathematical theorem file replaces each generated `Proofs/foo.lean` plus
  `Results/foo.lean` pair.  `Proofs/All.lean` and `Results/All.lean` disappear.
- Topic `All.lean` files import canonical theorem files directly; the two root
  facades are `AlgebraicCurves.All` and `JacobianVarieties.All`.
- Every maintained source is reachable from exactly the appropriate root
  facade, with no missing local import and no import cycle.
- No `sorry`, `admit`, new axiom, warning suppression, or stale compatibility
  attribute is accepted as a substitute for a proof or a clean build.
- Bare `import Mathlib` is not accepted in maintained AC/JV sources.  Each file
  imports the smallest stable Mathlib modules and local mathematical modules
  that provide the declarations it actually uses; this is verified after the
  source graph has stabilized rather than hidden behind a global umbrella.

## Jacobian completion contract

Source migration and a completed Jacobian construction are separate milestones.
The maintained public target has two layers:

- **T0:** for a smooth, proper, geometrically irreducible relative curve over a
  field, expose its genus and unpointed `Jacobian`, with group-object structure,
  relative dimension equal to the genus, smoothness, properness, and geometric
  irreducibility.  A chosen point supplies an Abel--Jacobi map sending that point
  to zero and satisfying the usual unique factorization into smooth proper
  geometrically irreducible group objects.
- **T1:** construct the unpointed `PicardZeroScheme C = Pic⁰(C/k)` over an
  arbitrary field as a commutative group scheme, prove smoothness, properness,
  geometric integrality, the `H¹(C, O_C)` dimension formula, arbitrary field
  base change, and classification of geometric points by degree-zero line
  bundles.  `JacobianVariety` is this same object, not a second construction;
  base points occur only in Abel--Jacobi maps and rigidification.

The construction order is part of the acceptance contract:

1. Curves, line bundles, divisors, and the family-compatible `D ↦ O(D)` map.
2. Absolute and relative coherent cohomology, curve vanishing,
   Riemann--Roch, finiteness, base change, and semicontinuity.
3. Hilbert schemes of finite-flat subschemes, universal divisors, and the
   high-degree Abel map.
4. The fppf Picard functor, degree components, representability, and gluing of
   translated Hilbert charts.
5. Descent of pointed local constructions, or direct unpointed gluing, with
   choice independence and cocycles.
6. The geometry and group structure of `Pic⁰`, followed by Abel--Jacobi.
7. Albanese factorization, including finite-family sums, linear-equivalence
   invariance, kernel-pair equality, and effective-epimorphism descent.
8. Acceptance tests for T0 and T1, `P¹`, `Hilb⁰`, `Hilb¹`, genus one, field
   base change, and Picard points.

Conditional packages such as `RepresentsRelSubPic`, `SymmetricPowerPackage`, or
`UnivDivisorPack` do not by themselves construct their hypotheses.  Likewise,
`EffectiveEpi` alone does not construct finite sums or prove kernel-pair
equality, and connected fibres alone do not imply that a morphism is constant.
Commutativity of a target group object in the T0 universal property must be
derived rather than added as a stronger public assumption.  Acceptance also
includes `Jac(E) ≅ E` in genus one and closed-immersion behavior of Abel--Jacobi
for positive genus.

[anthropics/fermats-last-theorem](https://github.com/anthropics/fermats-last-theorem).
The obsolete row-level migration manifest was removed after the source-tree
collapse; it remains recoverable from Git history at commit `e82050e8`.
